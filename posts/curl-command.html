cURL Command Reference & libcurl Developer Guide

Updated: September 2026 • Comprehensive Reference Guide

cURL is a command-line utility used for transferring data via URLs. It supports a broad range of protocols including DICT, FILE, FTP, FTPS, Gopher, HTTP, HTTPS, IMAP, IMAPS, LDAP, LDAPS, POP3, POP3S, RTMP, RTSP, SCP, SFTP, SMTP, SMTPS, Telnet, and TFTP.

It natively handles SSL certificates, HTTP POST/PUT operations, FTP/HTTP uploads, proxies, cookies, user authentication (Basic, Digest, NTLM, Negotiate, Kerberos), proxy tunneling, and other advanced networking tasks. Below is a categorized reference of essential cURL usage patterns and libcurl C library integration.

1. Viewing Web Page Source Code

By default, cURL outputs the response body directly to standard output (stdout). You can redirect output to a file or follow HTTP redirects. 

# Output web page HTML source code to stdout
curl www.example.com

# Redirect output to a file or specify output filename with -o (displays download progress)
curl www.example.com > example.html
curl -o example.html www.example.com

# Automatically follow URL redirects using -L / --location
curl -L www.google.com

2. Downloading Files

Download files by specifying a custom local filename (-o) or keeping the original filename from the remote server (-O). 

# Specify custom output filename with -o
curl -o font.zip http://font.ubuntu.com/download/ubuntu-font-family-0.80.zip

# Preserve remote filename using -O (uppercase O), similar to wget
curl -O http://font.ubuntu.com/download/ubuntu-font-family-0.80.zip

Batch Downloads & Pattern Matching:

# Download multiple files sequentially
curl -O http://www.example.com/img1/img[0-9].png

# Download files across multiple directories
curl -O http://www.example.com/{img1,img2}/img[0-9].png

# Prevent overwriting files across directories using pattern variables (#1, #2)
curl -o #2_#1.png http://www.example.com/{img1,img2}/img[0-9].png
# Output filenames: img1_img0.png, img2_img0.png, etc.

Resuming Interrupted Downloads & Chunking:

# Check local file size in bytes
wc -c ubuntu-font-family-0.80.zip
# Example output: 20480 ubuntu-font-family-0.80.zip

# Resume download from byte offset (-C offset)
curl -C 20480 -O http://font.ubuntu.com/download/ubuntu-font-family-0.80.zip

# Download specific byte ranges using -r / --range (in bytes)
curl -r 0-10240 -o part1 http://font.ubuntu.com/download/ubuntu-font-family-0.80.zip
curl -r 10240-20480 -o part2 http://font.ubuntu.com/download/ubuntu-font-family-0.80.zip
curl -r 20480- -o part3 http://font.ubuntu.com/download/ubuntu-font-family-0.80.zip

# Merge chunked files into a single archive
cat part[123] > ubuntu-font-family-0.80.zip

FTP Downloads:

# Anonymous FTP download
curl -O ftp://ftp.software.ibm.com/software/PCLW32_EN_IB_0012.zip

# Authenticated FTP download
curl -u "user:password" -O ftp://example.com/path/file
curl -O ftp://user:password@example.com/path/file

3. Uploading Files (PUT / FTP)

Upload files using the -T / --upload-file option via FTP or HTTP PUT. 

# FTP file upload
curl -T a.txt -u user:pass ftp://example.com/path

# HTTP PUT upload
curl -T a.txt http://www.example.com/path

4. Inspecting Response Headers

Use -I / --head to fetch response headers only, or -i / --include to display headers along with the body. 

curl -I www.example.com
# Response snippet:
# HTTP/1.1 200 OK
# Server: nginx/1.1.19
# Date: Mon, 10 Sep 2012 06:17:19 GMT
# Content-Type: text/html; charset=utf-8
# Connection: keep-alive

5. Verbose Request Debugging

Use -v / --verbose or trace options to inspect request headers, handshakes, and diagnostic logs. 

# Verbose HTTP connection details
curl -v www.example.com

# Comprehensive binary and ASCII trace logging to a file
curl --trace example.txt www.example.com
curl --trace-ascii example.txt www.example.com

6. Sending GET and Form POST Data

# GET request with query parameters
curl www.example.com/codes/?page=1

# Form URL-encoded POST request using -d / --data
curl --data "user=warm&password=lab" www.example.com
curl --data "month=Aug. 1" www.example.com

7. Setting Referer Headers

Simulate navigation sources or bypass basic anti-hotlinking checks using -e / --referer. 

curl -e http://www.example.com www.google.com

8. Customizing User-Agent

Specify custom client application or browser identity headers with -A / --user-agent. 

curl --user-agent "user agent info" www.example.com

9. Handling Cookies

Pass custom cookie values with -b / --cookie or export server-assigned cookies/headers using -D / --dump-header. 

# Send inline cookies
curl --cookie "key=value" www.example.com

# Dump response headers and cookies to header1.txt
curl -D header1.txt www.example.com

# Re-use dumped cookie state in a subsequent request
curl -D header2.txt -b header1.txt www.example.com

10. Adding Custom HTTP Headers

# Add a custom key-value header
curl --header "Key: value" http://www.example.com

# Specify content acceptance header
curl -H "Accept: application/xml" http://www.example.com

11. HTTP Authentication

# Login with basic authentication credentials
curl --user "user:pass" http://www.example.com

12. Using Proxy Servers

# Route traffic through a proxy server using -x / --proxy
curl -x 123.456.789.0:3188 http://www.example.com

13. SSL & Certificate Operations

Manage custom CA bundles, self-signed certificates, and mutual TLS (mTLS) authentication. 

# Standard HTTPS request
curl https://www.example.com

# Provide a specific CA certificate authority bundle
curl --cacert cacert.pem https://www.example.com

# Skip SSL/TLS certificate verification (-k / --insecure)
curl -k https://www.example.com

# Mutual TLS (mTLS) with client certificate and private key
curl -k --cert client.pem --key client.key https://www.example.com
curl --cacert cacert.pem -E client.pem --key client.key https://www.example.com

14. Additional Protocols: DICT Lookup

# Query a dictionary server via DICT protocol
curl dict://dict.org/d:warm

15. Modern REST APIs: JSON Payload & Multipart Uploads

For modern Web APIs, sending JSON bodies and multipart form uploads (e.g., uploading images via Web forms) are standard requirements. 

# Send JSON payload using explicit headers
curl -X POST https://api.example.com/v1/users \
  -H "Content-Type: application/json" \
  -d '{"name": "Alex", "role": "admin"}'

# Modern shorthand for JSON payload (curl 7.82.0+)
curl --json '{"name": "Alex", "role": "admin"}' https://api.example.com/v1/users

# Multipart Form Upload (multipart/form-data) using -F / --form
curl -F "username=alex" -F "avatar=@/path/to/image.png" https://example.com/upload

# Specify HTTP method explicitly (-X POST / PUT / PATCH / DELETE)
curl -X DELETE https://api.example.com/v1/posts/42

16. Performance Benchmarking & Diagnostic Metrics

Use the -w / --write-out flag to inspect network timing statistics, such as DNS resolution time, TLS handshake latency, and time-to-first-byte (TTFB). 

# Measure request latency breakdown
curl -s -o /dev/null -w "HTTP Status: %{http_code}\nDNS Lookup: %{time_namelookup}s\nConnect Time: %{time_connect}s\nAppConnect (TLS): %{time_appconnect}s\nStart Transfer (TTFB): %{time_starttransfer}s\nTotal Time: %{time_total}s\n" https://www.example.com

17. Script Resilience, Timeouts & Rate Control

# Silent execution but display errors (-sS), fail on HTTP errors (-f)
curl -sSf https://api.example.com/healthcheck

# Enforce connection and operation timeout limits
curl --connect-timeout 5 -m 15 https://www.example.com

# Automatic request retry on transient failures
curl --retry 3 --retry-delay 2 https://api.example.com/data

# Throttle maximum bandwidth download rate
curl --limit-rate 500k -O https://example.com/large-file.zip

# Enforce specific HTTP protocol versions (--http1.1 / --http2 / --http3)
curl --http2 https://www.example.com

18. Introduction to libcurl (C Library)

libcurl is a free, easy-to-use URL transfer library powering networking functionality across multiple platforms. It supports protocols including DICT, FILE, FTP, FTPS, Gopher, HTTP, HTTPS, IMAP, IMAPS, LDAP, LDAPS, POP3, POP3S, RTMP, RTSP, SCP, SFTP, SMTP, SMTPS, Telnet, and TFTP.

libcurl provides full support for SSL certificates, HTTP POST/PUT operations, FTP/HTTP form uploads, proxies, cookies, user authentication schemes (Basic, Digest, NTLM, Negotiate, Kerberos), resumed downloads, and HTTP proxy tunneling. Downloads for supported OS platforms are available at http://curl.haxx.se/libcurl/.

Build & Project Setup

  • iOS Development (Xcode): Download the iOS binaries, import the two .a library files and header files into your Xcode project. Update Header Search Paths and Library Search Paths in Build Settings to ensure proper compiler resolution.
  • Linux Compilation: Link libcurl using the compiler flag -lcurl or retrieve linker flags directly via curl-config --libs.

C Example: Basic HTTPS Request with File Output

#include <stdio.h>
#include <curl/curl.h>

int main(void)
{
    CURL *curl;
    CURLcode rc;

    curl_global_init(CURL_GLOBAL_DEFAULT);

    curl = curl_easy_init();
    if (curl) {
        curl_easy_setopt(curl, CURLOPT_URL, "https://www.example.com");
        curl_easy_setopt(curl, CURLOPT_FOLLOWLOCATION, 1L);

        curl_easy_setopt(curl, CURLOPT_SSL_VERIFYPEER, 1L);
        curl_easy_setopt(curl, CURLOPT_SSL_VERIFYHOST, 2L);

        curl_easy_setopt(curl, CURLOPT_SSLCERT, "client.pem");
        curl_easy_setopt(curl, CURLOPT_SSLKEY, "client.key");
        curl_easy_setopt(curl, CURLOPT_CAINFO, "servercacert.pem");

        FILE *fp = fopen("data", "w");
        curl_easy_setopt(curl, CURLOPT_WRITEFUNCTION, fwrite);
        curl_easy_setopt(curl, CURLOPT_WRITEDATA, fp);

        rc = curl_easy_perform(curl);
        if (rc != CURLE_OK) {
            fprintf(stderr, "curl_easy_perform() failed: %s\n", curl_easy_strerror(rc));
        }

        fclose(fp);
        curl_easy_cleanup(curl);
    }

    curl_global_cleanup();
    return 0;
}

19. libcurl C Advanced: Receiving Responses into Memory Buffer

In real-world application code, HTTP responses are rarely written to disk files. Instead, they are parsed directly in memory. The following callback dynamically grows a memory buffer using realloc. 

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <curl/curl.h>

struct MemoryStruct {
    char *memory;
    size_t size;
};

static size_t WriteMemoryCallback(void *contents, size_t size, size_t nmemb, void *userp)
{
    size_t realsize = size * nmemb;
    struct MemoryStruct *mem = (struct MemoryStruct *)userp;

    char *ptr = realloc(mem->memory, mem->size + realsize + 1);
    if (!ptr) return 0; // Out of memory

    mem->memory = ptr;
    memcpy(&(mem->memory[mem->size]), contents, realsize);
    mem->size += realsize;
    mem->memory[mem->size] = 0; // Null-terminate string

    return realsize;
}

int fetch_json_api(void)
{
    CURL *curl_handle = curl_easy_init();
    struct MemoryStruct chunk = { malloc(1), 0 };

    if (curl_handle) {
        curl_easy_setopt(curl_handle, CURLOPT_URL, "https://api.example.com/v1/data");
        curl_easy_setopt(curl_handle, CURLOPT_WRITEFUNCTION, WriteMemoryCallback);
        curl_easy_setopt(curl_handle, CURLOPT_WRITEDATA, (void *)&chunk);

        if (curl_easy_perform(curl_handle) == CURLE_OK) {
            printf("Fetched %lu bytes:\n%s\n", (unsigned long)chunk.size, chunk.memory);
        }

        curl_easy_cleanup(curl_handle);
    }
    free(chunk.memory);
    return 0;
}

20. libcurl C Advanced: Headers (`curl_slist`) & Async Multi Interface

To supply HTTP headers (e.g. Content-Type: application/json), build a linked list using curl_slist_append. For non-blocking parallel HTTP requests in C, use the curl_multi_* interface. 

// 1. Setting Custom HTTP Headers in C
struct curl_slist *headers = NULL;
headers = curl_slist_append(headers, "Content-Type: application/json");
headers = curl_slist_append(headers, "Authorization: Bearer YOUR_TOKEN");

curl_easy_setopt(curl, CURLOPT_HTTPHEADER, headers);
curl_easy_setopt(curl, CURLOPT_POSTFIELDS, "{\"key\":\"value\"}");

// Perform request...

curl_slist_free_all(headers); // Free header list memory after completion

// 2. Overview of Non-blocking Concurrent Transfers (curl_multi)
CURLM *multi_handle = curl_multi_init();
curl_multi_add_handle(multi_handle, easy_handle_1);
curl_multi_add_handle(multi_handle, easy_handle_2);

int still_running = 0;
do {
    curl_multi_perform(multi_handle, &still_running);
} while (still_running);

curl_multi_cleanup(multi_handle);
